B3. Intended use consistency
----------------------------
Suggested paper text:

Our use of the datasets is consistent with their benchmark-oriented intended
use: ARC-Challenge, MMLU, MMLU-Pro, and GPQA are public multiple-choice QA
benchmarks intended for evaluating model knowledge and reasoning. We use them
only as evaluation seeds and as baselines for studying distractor construction;
we do not train models on the benchmark items. Our generated artifacts are
intended for research on MCQA benchmark construction, distractor quality, and
model evaluation methodology. They should not be used as unsupervised
high-stakes educational tests or as replacements for expert-authored classroom
or certification exams without additional human review, accessibility review,
and validation with the target test-taking population. When releasing derived
artifacts, we will preserve source identifiers and license metadata so users can
respect the access conditions of the original datasets.


B4. PII / offensive content checks
----------------------------------
Ideas you can implement or mention:

1. Automated PII scan:
   Run a lightweight PII detector over question stems, answer choices,
   generated distractors, and reasoning traces. Flag emails, phone numbers,
   addresses, URLs, person names, IDs, and other structured identifiers.

2. Offensive / sensitive content scan:
   Run a toxicity or safety classifier over generated distractors and reasoning
   traces. Report the number of flagged items and manually inspect them.

3. Manual spot check:
   Manually audit a random stratified sample across dataset x generator x
   setting. For example, 30-50 items per dataset or 5-10 items per cell.

4. Dataset-card justification:
   Since ARC, MMLU, GPQA, and MMLU-Pro are public benchmark datasets rather
   than newly collected personal data, say that the risk is lower, but still
   state what you checked in your derived generations.

Suggested paper text after doing at least a basic scan:

We did not collect new human-subject data. Because our generated artifacts may
transform public benchmark questions into new answer options and reasoning
traces, we checked the released stems, answer options, generated distractors,

C2. Experimental setup / hyperparameter reminder
------------------------------------------------
Repo / git-history finding:

I did not find evidence of a formal hyperparameter search over model sampling
settings. The repo history does show engineering changes to prompts, parsing,
model support, scheduler behavior, vLLM startup arguments, and reasoning
policies. The final retained source generation runs used fixed settings per
stage:

- Final source generation stores:
  - results/inspect/generation/gemini_from_scratch_testing: max_tokens=10000,
    reasoning_effort=medium for all 32 successful .eval files.
  - results/inspect/generation/gen_gpt52_v2: max_tokens=10000,
    reasoning_effort=medium for all 42 successful .eval files.
  - results/inspect/generation/together_from_scratch_testing: max_tokens=10000
    for all 26 successful .eval files; 6 logs include reasoning_effort=medium
    in the Inspect plan config, while 20 omit it. In current code,
    reasoning_effort_for_model disables reasoning_effort for
    together/Qwen/Qwen3.5-397B-A17B, so this should be described as
    unsupported / unused for Qwen.
- Superseded / non-source generation directory:
  - results/inspect/generation/gen_gpt52_model_from_scratch_all has 20
    successful GPT-5.2 .eval files with max_tokens=2048 and
    reasoning_effort=medium. This directory is not the source for the strict
    GPT augmented store; datasets/augmented_filtered/strict/gpt points to
    datasets/augmented/gen_gpt52_v2/openai_gpt-5.2-2025-12-11.
- Final evaluation logs:
  - 1,270 successful evaluation .eval files use max_tokens=32768 and
    reasoning_effort=medium.
  - 118 successful GPT-5.4-mini evaluation .eval files use max_tokens=32768
    and reasoning_effort=high.
  - 45 EXAONE evaluation .eval files use max_tokens=32768,
    reasoning_effort=medium, plus extra_body={"chat_template_kwargs":
    {"enable_thinking": true}}.

Hyperparameter / policy changes found in git history:

- Generation max tokens changed in practice from a retained GPT-only 2048-token
  run to the final 10000-token source run. Treat this as an earlier/superseded
  generation attempt, not as a reported hyperparameter comparison, unless you
  used it in analyses.
- Evaluation max tokens are fixed at 32768 in final logs and README commands.
- GPT-5.4-mini evaluation uses high reasoning effort; other evaluation runs
  use medium reasoning effort where accepted.
- Commit 741a688f removed a Nemotron-specific "/no_think" system message, so
  final evaluation prompts use a single user message for all models.
- Commit bdf71e15 added model-specific vLLM startup and thinking support:
  model-specific max_model_len overrides, trust_remote_code for selected
  models, Nemotron mamba_ssm_cache_dtype=float32, Qwen FP8 quantization, and
  EXAONE/Qwen-thinking extra_body enable_thinking support.
- Commit f9c9c763 updated JSON parsing to accept final JSON after reasoning
  traces, which affects parsing robustness rather than model sampling.

We did not conduct a hyperparameter search over sampling settings. Generation
